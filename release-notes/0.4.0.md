amlc-lsp 0.4.0 updates compatibility with the official AMLC compiler and improves
symbol navigation and diagnostic positions in AppliedML editors.

## Changes

- Update the official AMLC dependency to `1f24fa97` and compile in Source mode.
- Add same-file navigation, references and rename for checked nested struct
  fields in storage paths, term form parameters and direct form calls.
- Track named types in checked `equal[Type]` expressions.
- Recover diagnostic positions from compiler error headers, including Unicode
  and CRLF sources. Errors in imported files keep their original messages
  without highlighting an unrelated position in the current document.
- Update the Lite Node regression baseline to `f58b465` while retaining the
  separate legacy AMLC baseline.

## Installation

In an OCaml 4.14.2 OPAM switch, install the versioned source:

```sh
opam pin add amlc-lsp.0.4.0 "git+https://github.com/arkenstone-lab/amlc-lsp.git#v0.4.0"
```

Accept the dependent-pin prompt to install the audited AMLC dependency. When
upgrading, an older AMLC source pin may need updating even if its package version
is still `0.1.0~preview`. AMLC is not in the central OPAM repository, so
`opam install amlc-lsp` alone does not install this release.

See the [installation guide](https://github.com/arkenstone-lab/amlc-lsp#install-the-server)
for system requirements and Nix builds.

## Editors

- The Zed extension targets the 0.4.0 server archives for macOS, Linux and
  x86_64 Windows. Each archive includes GMP and its corresponding source and
  license notices.
- The Visual Studio Code extension targets the 0.4 server release line. A VSIX
  is included for manual installation; Marketplace and Open VSX distribution
  are handled separately.
- Visual Studio Code and Neovim retain their OPAM installation commands. They
  require the audited AMLC package to be installed first and do not replace it.
  Existing servers found on PATH or in OPAM must be upgraded manually.

Analysis runs locally through the compiler library. This release does not
validate deployment or network linking. Cross-file references and rename remain
limited to interface imports and `implements`; the new symbol tracking is
same-file.
